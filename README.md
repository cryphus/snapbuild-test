# снэпбилд — тестовое задание Fullstack Developer

Расширение продуктового лендинга [snapbuild.ru](https://snapbuild.ru/) пятью новыми секциями
с сохранением визуального языка исходного сайта. Выполнено по расширенному варианту задания:
существующие секции (шапка → подвал) воспроизведены самостоятельно, новые блоки встроены
между ними в логичных местах.

## 1. Что сделано

- Воспроизведена вся структура исходного лендинга: шапка со sticky-навигацией и мобильным меню,
  hero, полоса логотипов, блок «Одна платформа — весь маркетинг», табы с демо-контентом по
  типам материалов, сравнительная таблица, безопасность, горизонтальная лента роадмапа,
  FAQ-аккордеон, финальный CTA и подвал.
- Добавлено пять новых секций (см. раздел 5), органично встроенных между существующими блоками.
- Собрана единая последовательная страница — без выделения новых блоков в отдельный экран.
- Проверена адаптивность на 375 / 768 / 1280 px, отсутствие горизонтального скролла и работа
  всех интерактивных элементов.

## 2. Опубликованная версия

**https://cryphus.github.io/snapbuild-test/**

## 3. Локальный запуск

Требуется Node.js 20+.

```bash
npm install
npm run dev
```

Приложение поднимется на `http://localhost:5173`.

Сборка продакшен-версии:

```bash
npm run build
npm run preview
```

## 4. Стек

- **Vite + React + TypeScript** — статическая сборка без бэкенда, удобна для публикации на
  GitHub Pages.
- Чистый CSS с переменными дизайн-системы (без Tailwind/UI-kit — чтобы не тянуть чужой
  визуальный язык поверх стиля снэпбилда).
- Шрифт **Manrope** (Google Fonts) — открытый аналог платного `TT Commons Pro`, используемого
  на оригинальном сайте.
- Деплой — GitHub Actions → GitHub Pages (`.github/workflows/deploy.yml`).

Структура проекта:

```
src/
  components/
    layout/     — Header, Footer
    sections/   — все секции лендинга (существующие и новые)
  data/
    siteContent.ts  — тексты и контент воспроизведённых секций сайта
    newSections.ts   — контент пяти новых секций
  styles/
    tokens.css   — переменные дизайн-системы, снятые с исходного сайта
    global.css   — базовая типографика, контейнер, кнопки, карточки
```

## 5. Пять новых секций

| Секция | Расположение | Интерактивность |
|---|---|---|
| **Кейсы использования** | после табов с демо-контентом (`#use-cases`) | — |
| **Тарифы** | после сравнительной таблицы, перед «Безопасность» | переключатель «Ежемесячно / Ежегодно» |
| **Интеграции** | после «Безопасность», перед роадмапом | — |
| **Отзывы клиентов** | после роадмапа, перед FAQ | карусель с навигацией стрелками и точками |
| **Форма заявки** | перед финальным CTA | клиентская валидация, состояние успешной отправки |

Тексты всех секций — по продукту снэпбилда (дизайн-система, маркетинговые материалы, AI),
без Lorem Ipsum.

## 6. Как анализировалась стилистика исходного сайта

Вместо визуальной оценки на глаз стили сняты напрямую из `computed styles` и CSS custom
properties боевого сайта (через DevTools/скрипты в браузере):

- **Типографика**: шрифт (`TT Commons Pro`), размеры и начертания h1–h6, letter-spacing,
  line-height для заголовков, текста и мелких лейблов.
- **Цвета**: фон страницы (`#f5f5f6`) и единственной секции с белым фоном (финальный CTA),
  нейтральная шкала (100–900), цвет текста и приглушённого текста, цвет разделителей.
- **Компоненты**: у сайта обнаружена собственная дизайн-система на ~500 CSS-переменных
  (`--card-*`, `--btn-*`, `--input-*`, `--chip-*`, `--tab-*`, `--accordion-*` и т.д.) — из неё
  взяты радиусы карточек (24px), кнопок (12px), инпутов (20px), толщина и цвет границ.
- **Сетка и отступы**: grid-gap карточек, вертикальные паддинги секций, ширина контейнера.
  Ориентировочные значения зафиксированы в `src/styles/tokens.css`.
- **Брейкпоинты**: найдены непосредственно в CSS сайта (767 / 768–1023 / 1024px) — совпадают с
  ориентирами ТЗ (375 / 768 / 1280).

Полный протокол анализа — в [`PLAN.md`](./PLAN.md), раздел 1.

## 7. Что удалось воспроизвести из исходной страницы

Воспроизведены все секции лендинга — структура, контент, графика и движение:

- **Шапка** — плавающая «таблетка» с полупрозрачным фоном и `backdrop-filter: blur(10px)`,
  при прокрутке появляется рамка и мягкая тень; мобильное меню с анимацией пунктов.
- **Первый экран** — карточка с фирменным градиентом, скриншот продукта, входные анимации
  (заголовок 1800ms, кнопка 1100ms с задержкой 420ms, медиа въезжает снизу).
- **Полоса логотипов** — поочерёдное появление на десктопе (шаг 90ms), бесконечная бегущая
  строка на мобильных.
- **«Одна платформа — весь маркетинг»** — три карточки с превью-изображениями.
- **Табы по типам контента** — переключение меняет и список пунктов, и крупное превью;
  у активного пункта градиентный индикатор. Всего 20 изображений (5 табов × 4 пункта).
- **Таблица сравнения** — выделенная колонка снэпбилда с градиентной рамкой и названием.
- **Безопасность** — акцентная часть заголовка залита градиентом, три иллюстрации.
- **Роадмап** — 11 карточек по месяцам, градиентные точки на линии таймлайна,
  перетаскивание мышью.
- **FAQ** — все 8 вопросов, аккордеон с анимацией иконки «плюс → минус».
- **Финальный CTA** — вторая градиентная карточка с текстурой и двумя плывущими пятнами.
- **Подвал** — навигация, документация, контакты.

Отдельно перенесены две системные вещи, определяющие облик сайта:

1. **Фирменный градиент** (`#ff6d3c → #ff6ba7 → #bb6dff`) — единственный цветовой акцент
   сайта.
2. **Флюидная шкала.** Оригинал не использует фиксированные px: размеры записаны как
   `calc(X / 14.4 * 1vw)` от макета 1440 (и 8.1 / 3.75 для планшета и мобильных). В проекте
   это сведено к переменной `--sp` — «один пиксель макета», см. `src/styles/tokens.css`.
   Совпадение проверено: заголовок первого экрана даёт ровно 67.5556px при вьюпорте 1280,
   как на оригинале.

Графика (47 файлов) перенесена в `public/assets/images` — это ассеты самого лендинга,
используемые в рамках воспроизведения по расширенному варианту задания.

### Появление секций

Секции выезжают снизу при прокрутке — сдвиг 32px и кривая
`cubic-bezier(0.16, 1, 0.3, 1)` взяты у оригинала. Реализация отличается двумя вещами,
и обе появились после проверки на опубликованной версии, а не «на всякий случай».

**Считаем по положению блока, а не через `IntersectionObserver`.** Оригинал использует
observer, но у него есть пробел: при переходе по якорю из меню страница перематывается
мимо нескольких секций, состояние пересечения между кадрами не меняется, колбэк не
приходит — и блоки остаются скрытыми, хотя пользователь их уже проскроллил. На живой
версии так «терялись» пять секций из одиннадцати. Проверка положения (`top` выше 90%
высоты экрана) такого пробела не имеет. Обработчик один на все секции, троттлится через
`requestAnimationFrame` и снимается, когда показывать больше нечего.

**Скрытие включается только после пробы.** Скрывать контент до события опасно: если
браузер не доиграет переход, секция останется невидимой навсегда. Поэтому перед
включением скрипт проверяет, что браузер действительно продвигает переходы, а не
застывает на начальном значении (такое встречается во встроенных webview без
композитинга — и именно на этом сценарии страница один раз оказалась пустой). Проба не
прошла или JS не выполнился — класс `js-reveal` не ставится, страница показывается
целиком без анимации.

## 8. Что не удалось реализовать и почему

- Точный шрифт `TT Commons Pro` — платный, не распространяется публично. Заменён на близкий по
  пропорциям Manrope с пояснением в токенах.
- Не воспроизводился внутренний CMS-слой оригинала (`data-cms-*` атрибуты, генерация разметки
  из шаблонов) — для статической копии он не нужен.
- Часть анимаций упрощена: у оригинала есть отдельные keyframes для «шайна» по тексту кнопок
  (`dds-btn-text-sweep`/`shine`); в копии кнопки используют статичную градиентную заливку
  текста и hover-подъём.
- Появление секций реализовано не через `IntersectionObserver`, как в оригинале, а по
  положению блока (подробности — в разделе «Появление секций» ниже). Визуально результат
  тот же, но без пробелов при перемотке по якорям.

## 9. Что бы улучшил при наличии дополнительного времени

- Оптимизировал бы вес изображений: часть исходных превью весит 300–900 КБ при отображении
  в 750px — стоит нарезать `srcset` под три брейкпоинта (у оригинала такие варианты есть).
- Довёл бы «шайн» по тексту кнопок и микро-анимации табов до оригинала.
- Провёл бы аудит контраста и focus-состояний по всем интерактивным элементам.
- Написал бы unit-тесты на валидацию формы и переключатель тарифов.

## 10. Использованные AI-инструменты

- **Claude (Anthropic)** — анализ ТЗ; снятие визуальных токенов исходного сайта через
  автоматизированный браузер (computed styles, CSS custom properties, брейкпоинты); разбор
  скачанных исходников оригинала (HTML, CSS, JS) для извлечения keyframes, флюидной шкалы и
  механики табов/роадмапа/reveal; генерация React-компонентов и контента секций; отладка;
  проверка сборки и адаптивности; настройка GitHub Actions деплоя.

Весь сгенерированный код проверялся в браузере и на опубликованной версии, а не принимался
на веру. Так были найдены и исправлены вещи, которые в первой итерации оказались неверными:

- вывод «сайт монохромный» — на деле у него есть фирменный градиент;
- фиксированные px вместо флюидной шкалы оригинала;
- размеры части элементов, разошедшиеся с оригиналом (радиусы, высота логотипов,
  пропорции превью, кегль заголовков) — сверены замерами на одной ширине;
- придуманная плашка с градиентным заголовком в блоке безопасности, которой в оригинале
  нет;
- анимация появления секций, из-за которой на живом сайте секции оставались невидимыми.

Последние случаи показательны: ни сборка, ни локальный запуск их не показывали — они
нашлись только при замерах против оригинала и проверке опубликованной страницы.
